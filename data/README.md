# data/ — oracle value arrays (not tracked in git)

This directory holds the `.npz` arrays (gitignored) whose JSON siblings in
`artifacts/` carry the published numbers:

| file | contents | size class |
|---|---|---|
| `phase1_values_n3.npz` | VAL/DTC/STMW arrays over 1,032 legal states | KB |
| `phase1_values_n4.npz` | same over 154,888 states | ~1 MB |
| `phase1_values_n5.npz` | same over 6,744,724 states | ~10-30 MB |
| `class_values_<class>.npz` | per-class arrays (ENC, VAL, ...) for the 7 K2P+N classes | KB-MB |

They are **not committed** on purpose:

1. They are fully regenerable from the committed oracle scripts in minutes
   to hours (REPRODUCE.md Sec. 1 and Sec. 3; the N=5 solve is ~110 s).
2. Git is the wrong tool for multi-megabyte binary arrays.

## Distribution plan

The arrays will be deposited on Zenodo (with a DOI) upon first publication
of the papers; this file will then carry the DOI and the exact file
manifest. Until then, the arrays are reproducible from source in the
authoring sandbox, and the smallest class array (kn N=3) is regenerated by
the CI gate on every push as a spot check.

## Checksums

To be added at the Zenodo deposit (SHA256 per file). The JSON artifacts in
`artifacts/` are the integrity reference for every published number; the
arrays only need to agree with them (e.g. legal-state counts and the
verification gates).
